# Correctness review: adopt-specflow

Dimension: **correctness** only. Material reviewed: prose, agent instructions,
config and ignore rules, plus two comments. No application code changed, so the
overlay's mutation tools (`cargo mutants`, manual QML mutation) have nothing to
mutate; every claim was checked by reading it against the tree or running the
named command instead. What that cannot see: whether the plugin's agents, once
the project's own files are gone, behave the way the overlay assumes. That is
only observable by dispatching them.

Each finding below was checked against the tree at `HEAD` (`36389f7`).

      **Scenario:** `What Changes` lists "Add `openspec validate --specs --strict` to `ci.yml`", `Impact` lists `.github/workflows/ci.yml` under "Files edited", and Open question 2 ends "Not decided here". `git diff origin/main...HEAD --stat` shows `ci.yml` untouched, `design.md` Decision 6 records the step as deferred to #93, and the PR body says the owner moved it.       **Measured:** `git grep -n "ci.yml" -- openspec/changes/adopt-specflow` returns the three proposal lines above beside design Decision 6's "nothing in `ci.yml` changes here".
      **Outcome (`spec-writer`): fixed.** What Changes drops the CI bullet and gains a "Not in this change" paragraph naming issue #93; the Capabilities paragraph no longer claims the step is recorded in the overlay's `## CI gates`; Open question 2 records the owner's answer (moved to #93) as question 1 records its; Impact moves `ci.yml` to a "Not edited" line. - [ ] **`dev-writer`** — `docs/e2e.md:372-380` — the embedded-home isolation claim ignores that the module derives the home from `XDG_DATA_HOME` first
      **Scenario:** the new paragraph says that "under sitometres' throwaway `$HOME` a spec can make a fresh embedded home", removing "both the dependency on a developer's profile and the two-Basecamps contention". But `node-paths` ("The embedded home is derived only from the module's own data directory") and `embedded-identity` derive the home from `XDG_DATA_HOME`, falling back to `$HOME/.local/share` only when it is unset, and `local.yaml:445-447` says the same. A developer whose shell exports `XDG_DATA_HOME` (common on desktop sessions) gets the embedded home under their real data directory whatever `$HOME` is. A spec written from this paragraph then calls `createEmbeddedIdentity` against their real embedded home: it either refuses ("occupied", a confusing failure) or, on a first run, creates a permanent identity there, which is the thing the new "never point a test at the real home" rule in `docs/rust-ffi.md` exists to prevent. Nothing in `docs/e2e.md` mentions `XDG_DATA_HOME` (`git grep -n XDG docs/e2e.md` is empty), and the paragraph's own hedge ("reasoning from the specs, not a run") covers whether a spec does it yet, not this precondition.
      **Severity:** defect in guidance, medium. The fix is a sentence naming the precondition: sitometres must also redirect, or the shell must not export, `XDG_DATA_HOME`. Whether sitometres overrides it is unmeasured here.

- [ ] **`dev-writer`** — `.gitignore:62-66` (comment at `:23-29`) — the specflow block re-admits four directories wholesale, including `.claude/skills/`, which `lgs init` generates
      **Scenario:** the rewritten comment directly above says "re-admit files by name where you can, and a directory only when everything in it is meant to be tracked", then `!.claude/skills/`, `!.claude/commands/`, `!.claude/hooks/` and `!.claude/specflow/` re-admit directories. `CLAUDE.md:446` still says `lgs init` generates `.claude/skills/` and that it goes stale on upgrade.       **Severity:** defect, low (a hazard the old rules did not have; no file is wrongly tracked today). The block is specflow's own output, so the repair may belong in the overlay's `## Never commit` rather than the ignore file.
