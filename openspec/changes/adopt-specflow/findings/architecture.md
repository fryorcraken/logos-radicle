# Findings: architecture

Dimension: **architecture** only (where each fact lives, one copy per rule,
whether the shape of the documents makes the next change easy). Correctness,
security and readability are other instances'. The material is prose, agent
instructions, config and ignore rules, so "architecture" here means information
architecture, judged against the piece's own aim ("one copy of each flow rule";
two copies of a rule drift) and the specflow block's "How to shape a change".

No mutation tool applies: nothing here is Rust, QML or C++ that a test reads,
and `cargo mutants` has no target in a prose diff. The checks I ran instead were
`git grep` for every deleted file name outside the archive (clean: only the
specflow block's generic `.claude/agents/` sentence and this change's own
folder), `git check-ignore --no-index` on the `.gitignore` re-admits,
`openspec validate adopt-specflow` (passes, `skip_specs` honoured), and reading
each deleted agent file against the overlay for repo-specific rules that did not
move. I did not run the overlay's cd-free `nix build ./radicle#checks...` form.

## Areas that were clean

- **Dangling references.** `git grep -E "PLAN\.md|\.claude/agents|RUNNER\.md|flow README|agents/README"` outside the archive returns the block's generic line and this change's own folder only. No workflow, script or spec cites a deleted file or a `CLAUDE.md` section that this piece removed (every section name cited from `docs/`, `scaffold.toml`, source comments and tests still exists).
- **Where PLAN.md's durable rules landed.** Platform scope, the real-home rule, the two-home rule, the embedded e2e lesson and the sitometres sentence each sit in the trigger doc a reader would open for that work (`docs/rust-ffi.md`, `docs/e2e.md`), `CLAUDE.md`'s "Where to look" row for `rust-ffi.md` was widened to match, and the platform claims check out against `ci.yml`'s matrix, `Cargo.lock` and the absence of `cfg(unix)`/`target_os` in the crate. Every other forward-looking passage has the issue Decision 1 names (checked against `gh issue list`) except the one flagged above.
- **Overlay versus deleted agent files.** I read the deleted `code-reviewer`, `dev-writer`, `closer`, `README` and `RUNNER` text for repo-specific rules; apart from the findings above, what is not in the overlay is either the plugin's (branch table, stage block, push sequence, probes) or recorded elsewhere in `CLAUDE.md`.
- **Slimmed `CLAUDE.md`.** What remains above the block is this repo's evidence (the `lgs` section, measured worktree traps, worked examples, release decisions), the internal "below"/"above" cross-references still resolve, and the stale claims Decision 4 lists are fixed in the file.
- **Change shape.** One piece, the refactor-then-move order (rules land before their source is deleted) is what the commits do, and `.openspec.yaml` carries `schema:` beside `skip_specs: true`.
